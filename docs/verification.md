# 開発時の検証

## 元MOD更新時の検証

元MODを更新した場合は、現在のDLLに対する動作検証を使用します。

```text
python tools/verify.py --current --baseline artifacts/baseline
```

READMEの参照先を設定し、`baseline/saves` に既存セーブのコピーを置きます。このモードには、移行時の旧DLLや比較結果は不要です。結果は `artifacts/current-verification-report.json` に出力します。

- 翻訳パッチの対象解決、分岐先・例外処理・文字列以外の命令の維持
- XAMLのバインディングと画面構造、キャンペーンの識別子とゲーム設定の維持
- 基地・空母・造船所の兵装表示と選択キー、数量計算の維持
- 補給拠点の守備隊数と、探知元・自軍センサー情報の分類の維持
- 個艦名・艦級名の表示変換と既存セーブの読み込み
- 初期化失敗時のログと、見つからない翻訳対象のスキップ

重点確認するキャンペーンは従来の `east_asia_1985`（DCM Pacific 1985: Island by Island）です。新キャンペーン全体の日本語化は今回の重点対象に含めませんが、共通画面や同じ原文の翻訳は適用されます。キャンペーンIDによる翻訳の除外は行いません。

### 翻訳漏れと未使用データの監査

登録済みの翻訳対象が解決できることや、ゲーム処理を壊さないことだけでは、翻訳漏れは検出できません。現行MODの表示元を起点に、次も確認します。

- 埋め込みXAMLの表示属性と、DLL内で組み立てるXAMLの属性を共通辞書と照合します。共通辞書はXAML専用で、メソッド別辞書の代わりにはなりません。
- キャンペーン設定の表示項目と `texts` を、実際に翻訳した設定と照合します。`texts` はDLL内の共通文を上書きするため、共通文の対訳だけでは足りません。
- 全メソッドの文字列を調べ、未登録の英文候補とその直後の命令を `artifacts/method-literal-review.json` に出力します。登録済みメソッドだけを調べる方式は使いません。
- 辞書の各項目が、現行XAML・対象メソッドの原文・インストール済みキャンペーンの表示項目に存在するか確認します。表示整形処理が使用するテンプレートは、元DLLに直接存在しなくても保持します。

監査は、XAMLと重点対象キャンペーンの未翻訳表示、未使用辞書、名前付き置換項目の欠落をエラーにします。メソッド内の英文候補には内部キー、診断ログ、略語も含まれるため、出力された使用箇所を人が確認して分類します。この候補数は、そのまま翻訳漏れの件数を意味しません。

キャンペーン固有文が共通文より優先される場合の日本語表示、名前付き置換、固有文が未指定・空の場合の共通文への切り替え、未登録文と内部キーの維持は、元MODの実際の文言取得処理を呼び出して検証します。監査に合格しても、全画面の描画や保存済みの過去の通知文まで確認できたことにはなりません。

### 表示の分岐と操作の検証

分岐命令が同じでも、比較に渡す文字列が変われば表示や動作は変わります。生成元・保存書式・読み取り側・UIの設定先をつなげて確認します。

- 報告書を生成して再解析し、見出し、章、本文、結びが欠落しないことを確認します。元の報告書書式は翻訳せず、画面の見出しだけを翻訳します。
- 元のメッセージ行生成処理を実行し、新規報告・既存英語報告・既存日本語報告で要約と「読む」ボタンが維持されることを確認します。描画部品のみを検証用に代替し、分類と表示条件は元の命令を実行します。
- 戦闘結果は内部で英語の値を維持し、UIへの設定時だけ `display.battleOutcome` で翻訳します。元の色分け分岐と戦績計上を、勝利・敗北・引き分けの各ケースで確認します。
- 元の削除コールバックを実行し、最初のクリックでは確認だけを表示し、次のクリックで削除操作へ進むことを確認します。ファイル操作は代替し、実際のセーブは削除しません。
- 分遣隊名、戦闘イベント名、ブリーフィングの章と命令行について、英語と従来の日本語表記で認識結果が変わらないことを確認します。旧表記への対応は読み取り時だけ行い、保存内容を変換しません。

翻訳される原文が文字列比較・正規表現にも現れる候補は `artifacts/comparison-literal-review.json` に出力します。近接命令から候補を抽出するため、無関係な別の引数も含まれます。使用箇所と生成元を照合し、疑わしい箇所は実際の分岐を通す検証で確認します。候補の存在だけで不具合とは判断しません。

## 移行時の比較検証の実施条件

`tools/verify.py` は、独立DLLへの移行時に取得した基準データと現在の実装を比較する開発用ツールです。通常のビルドには不要です。

基準データには従来版のDLL、翻訳データ、実行結果、既存セーブのコピーが必要です。これらはリポジトリや配布物に含めていません。基準データを保管していない環境では、この比較検証を実行できません。

実行時には、READMEの手順で `Directory.Build.local.props` を用意し、`SeaPowerDir`、`AnchorChainDir`、`OriginalModDir` を設定します。ビルドと検証プログラムは同じ設定を使います。

基準データの構成は次のとおりです。

```text
baseline/
  runtime-output.json
  installed-package/
    DynamicCampaignJapanese.dll
    rules.json
    texts.json
    campaign-texts.json
  saves/
    （検証するキャンペーンのセーブJSON。サブフォルダーも対象）
```

`runtime-output.json` には、移行時に取得したXAMLの原文・翻訳結果と、キャンペーン設定の原文・翻訳結果を使用します。`installed-package` には、その結果を取得した従来版DLLと旧形式の翻訳データを置きます。現在のDLLや `translation-data.json` を置いて基準データの代わりにすることはできません。

## 実行

プロジェクトルートで実行します。

```text
python tools/verify.py --baseline artifacts/baseline
```

WSLでは `python3` を使用し、基準データをWindowsドライブ上に置きます。`--baseline` で基準データの保管先を変更できます。省略時はプロジェクト内の `artifacts/baseline` を使います。基準データが不足している場合は、エラーとして不足するファイルを表示します。

検証対象は次のとおりです。

- XAML、翻訳処理の命令列、キャンペーン設定、キャッシュ済み表示名の従来版との一致
- バインディング用プロパティ名の維持
- 初期化失敗時のログと、翻訳対象が見つからない場合の動作
- 個艦名・艦級名の表示変換、辞書にない独自名称の維持、NATO名称設定と翻訳データの上書きへの対応
- テスト用の仮の艦名による、専用辞書の優先順位、未登録時の既存変換、ユニット別の適用範囲、辞書の再読み込み防止
- 既存セーブの読み込みと、表示変換前後の保存内容の一致

結果は `artifacts/verification-report.json` に出力します。ログと検証用に生成したデータも `artifacts` に保存します。

## ゲーム上での確認

ゲームを完全に終了してから、生成した配布フォルダーを `Sea Power_Data/StreamingAssets/DynamicCampaignJapanese` に配置して再起動します。旧DLLのバックアップは、ゲームがMODを読み込むフォルダーの外に保管します。

日本語表示、新規キャンペーンの開始、既存セーブからの再開を確認します。個艦名と艦級名は、基地・艦隊・詳細・編成・出撃などの画面で確認します。比較検証だけでは、実ゲームでの描画と操作は確認できません。

## 実装上の前提

今回の検証対象は元MOD 0.25.0です。プログラム内では元MODのバージョンによる制限を設けず、見つからない翻訳対象はログに記録してスキップします。

翻訳パッチは、元MODのメインメニュー初期化が完了してから適用します。画面ライブラリの準備前にUI型をパッチすると型の初期化に失敗するため、この順序を守ります。

適用時は、起動ログに `Independent Japanese localization` と `Japanese ship-name display translation active` を含むメッセージが出力されます。初期化や個別パッチが失敗した場合もログに記録します。

個艦名は、起動時に読み込んだ `campaign-ship-names.json` のユニットIDと元の艦名の対訳を優先し、未登録ならゲームが読み込む英語・日本語の艦名データを使用します。艦級名は従来どおりゲームの艦名データを使用します。変換は画面表示時だけ行い、対応のない名称、内部の艦名、キャンペーンID、ユニット識別子、セーブ形式を変更しません。
